## Project Description ##

This projects goal is the implementation of a temporal knowledge graph for RAG using local neo4j + gds plugin running in docker and python.
The ingestion high level runs like this:
Documents are chunked and then send to an embedding model to get vector embeddings.
Furthermore each chunk is sent to a LLM for time, entity and relationship with description extraction.

The chunks are inserted with their vector embeddings into the neo4j db.
The entities are also inserted into the neo4j db. There is a deduplication logic running IoU on top bm25 search results of aliases of the entity names within the neo4j db.
The relations between entites are also inserted as edges. Each relation can have a start and end date. Multiple relations between the same entities with the same content are allowed as long as the time of the relation description differs. For example company A did a deal with company B in 2021 is edge 1, while company A did a deal with company B in 2023 is edge 2.
The relationship description is also sent to an embedding model to get the vector embeddings of the llm produced relationship description.
The edge deduplication logic upon insertion of new edges goes like this:
If source and target entity and start and end date are the same do a cosine similarity comparison between already existing edge description embedding and the embedding of the potential new edge. If a threshold is surpassed the edges are merged. In all other cases a new edge is created.
Chunks in the db have links to the entities and edges that are mentioned in them. Moreover chunks also have links to the source document that contains them.
The source document is stored with a name and meta info such as last modified date and URI.

Retrieval happens in the following way: An user asks a question. This question is sent to an embedding model as well as to a LLM.
The LLM extracts entities and time info.
Entities and edges between these entites that fit into the extracted time range (if time range is null only the start or end date or none at all is taken, I guess...) are searched for by top k bm25 search of name aliases that match the extracted entity name from the user query and
the query embedding is used to find edges by similar edge description embeddings.

On this subgraph a personalized page rank algorithm is run to get the best edges.

Additionally a vector similarity search on the chunks is run to get the top k most similar chunks compared to the query.

Then the results of the edge search ppr and the vector chunk search are fused together using reciprocal rank fusion.

The retrieved context is formatted and then send to a LLM alongside the users question for question answering.
